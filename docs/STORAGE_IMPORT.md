# Обновление сроков через /sl

## Однократная подготовка

Применить в Supabase SQL Editor файл `docs/migrations/20261018_storage_times.sql`.
Он добавляет только каталог, историю версий и служебную функцию публикации.
Действующие таблицы/данные не удаляются. Сам Excel эта миграция не применяет.
Миграция идемпотентна. Пока она не применена, калькулятор использует встроенные
сроки с явной подписью, а бот не сможет подтвердить сохранение.

## Использование

1. Главный админ (Telegram ID 818748106) пишет `/sl` в личном чате бота.
2. Прикрепляет XLSX до 10 МБ в формате OPS: лист «Общее», A–I, строка заголовков 5.
3. Получает полный список изменений текстовым файлом и примечания.
4. Нажимает «Применить» либо «Отмена». Файл/подтверждение ожидаются 15 минут.
5. Сотрудники получают новую версию при открытии калькулятора, максимум через
   30 секунд открытого раздела или после перезагрузки мини-приложения.

Файлы без предварительного `/sl` по-прежнему обрабатываются существующим
импортом табеля. Старый CLI `storage_import.py` сохранён без изменений.
Новый строгий парсер находится в `storage_catalog_import.py`.

## Правила

- Без подтверждения публикации нет. Отсутствующие продукты сохраняются.
- Разные условия производства не суммируются: показываются отдельными вариантами.
- Температуры и выдержка внутри скобок не прибавляются к общему сроку.
- Недостающий общий дефрост-срок выводится из разморозки + последующего хранения.
- Противоречивые сроки, дубли, формулы, неизвестные единицы блокируют импорт.
- Повторный запрос публикации идемпотентен. Изменение каталога другим запросом
  после предпросмотра требует нового просмотра, а не затирает свежие сроки.
- Каждая опубликованная версия сохраняется в истории. Для отката оператор может
  повторно импортировать прежний Excel. Исходная встроенная версия остаётся в Git.
- В браузере нет прав записи. Публикация доступна только service_role через RPC
  с проверкой ID главного администратора. История версий закрыта от anon/authenticated.
- Оригинальный Excel не публикуется в Git. В базе хранятся разобранные данные,
  имя источника, контрольная сумма и сведения о публикации.

## Проверки

`python -m unittest discover -s tests`

`node tests/storage_catalog_client.cjs`

`PGLITE_CI=1 node tests/storage_catalog_database.mjs` (в CI после установки PGlite).

Миграция проверяется на изолированном PostgreSQL/PGlite: повторное применение,
история, идемпотентность, конфликт версий и запрет записи от anon.
